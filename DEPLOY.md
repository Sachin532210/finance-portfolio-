# Deploying Finance Track for free

Three pieces, three free tiers:

| Piece | Host | Free tier reality |
|---|---|---|
| React frontend | Vercel (or Cloudflare Pages) | Genuinely free, custom domain, no card |
| FastAPI backend | Render | Sleeps after 15 min idle; first request then takes ~50s |
| MySQL | TiDB Cloud Serverless | MySQL-compatible, works with the bundled PyMySQL driver, no card |

Total cost: nothing, unless you add an OpenAI key (usage-billed). Without one the
app falls back to its built-in financial engine, which runs the same
calculations and gives real answers — the deployment is fully functional either
way.

---

## Before you start

Push the project to GitHub. Check that `backend/.env` is **not** in the commit:

```bash
git status --short | grep -i "\.env$"
```

That should print nothing. `.gitignore` excludes `.env` and `.env.*` while
keeping the `*.example` templates.

---

## 1. Database — TiDB Cloud Serverless

1. Sign up at <https://tidbcloud.com> and create a **Serverless** cluster (free
   tier, no card).
2. Open **Connect**, keep **Connection Type: Public Endpoint**, then click
   **Generate Password**. Copy it immediately - TiDB shows it once.
   Note the host, the port (**4000**, not 3306) and the username, which looks
   like `LYNY4kiS1aocu27.root`.
3. In the SQL editor, create the schema:

   ```sql
   CREATE DATABASE finance_track;
   ```

   The app creates every table itself on first boot, so there is no migration
   step. It also tries `CREATE DATABASE IF NOT EXISTS` at startup and treats a
   permission error there as normal, provided the database is reachable.

   If you would rather use the `test` database TiDB starts you with, set
   `DB_NAME=test` instead and skip this step.

### TLS

TiDB's public endpoint refuses plaintext connections. The app handles this
automatically: any `DB_HOST` that is not `localhost` / `127.0.0.1` connects over
TLS, verified against the `certifi` CA bundle. Nothing to configure.

Overrides exist if you need them - `DB_SSL=true|false` to force it either way,
and `DB_SSL_CA=/path/to/ca.pem` for a private CA.

**Alternatives:** Aiven (free MySQL, port 3306) or Clever Cloud. For PostgreSQL
instead (Neon, Supabase), set `DB_ENGINE=postgresql` and `DB_PORT=5432`, and add
`psycopg[binary]` to `backend/requirements.txt` — the app ships with the MySQL
driver only.

## 2. Backend — Render

1. In Render choose **New → Blueprint** and point it at your repository. It
   reads `render.yaml` from the repo root.
2. Render prompts for every variable marked `sync: false`. Fill in:

   | Variable | Value |
   |---|---|
   | `DB_HOST` | e.g. `gateway01.ap-southeast-1.prod.aws.tidbcloud.com` |
   | `DB_PORT` | `4000` (already defaulted in the blueprint) |
   | `DB_USER` | e.g. `LYNY4kiS1aocu27.root` |
   | `DB_PASSWORD` | the password you generated in step 2 |
   | `CORS_ORIGINS` | your frontend URL, e.g. `https://finance-track.vercel.app` |
   | `OPENAI_API_KEY` | leave blank unless you want the LLM coach |
   | `MARKET_DATA_API_KEY` | your Finnhub key, or blank |

   `SECRET_KEY` is generated by Render automatically and then held constant.
   `ENVIRONMENT=production` and `DEBUG=False` are already set in the blueprint —
   leave them that way. Production mode is what puts the `Secure` flag on the
   session cookie, and `DEBUG=False` is what stops raw exception text being
   returned to the browser.

3. Deploy, then confirm it is healthy:

   ```bash
   curl https://YOUR-SERVICE.onrender.com/health
   ```

   Expect `"status":"ok"` and `"database":{"connected":true,...}`. If
   `connected` is false, the `DB_*` values are wrong — the error string in that
   response says which part failed.

Interactive API docs are at `https://YOUR-SERVICE.onrender.com/docs`.

**Alternatives:** `backend/Dockerfile` is included for hosts that need an image
(Koyeb, Fly.io, Railway, Cloud Run). Those do not sleep on their free tiers.

## 3. Frontend — Vercel

1. Edit `frontend/vercel.json` and replace the backend host in the first rewrite
   with your Render URL:

   ```json
   { "source": "/api/:path*", "destination": "https://YOUR-SERVICE.onrender.com/api/:path*" }
   ```

2. In Vercel, **Add New → Project**, import the repo, and set **Root Directory**
   to `frontend`. The framework preset, build command and output directory come
   from `vercel.json`.
3. Deploy.

### Why the rewrite matters

The app authenticates with an **httpOnly session cookie**. In development, Vite
proxies `/api` to the backend so the browser sees one origin. That proxy does
not exist in a production build.

The rewrite reproduces it: the browser only ever talks to
`https://your-app.vercel.app`, and Vercel forwards `/api/*` to Render
server-side. The cookie stays first-party, `SameSite=Lax` keeps working, and
**no application code changes**.

If you instead point the frontend directly at the Render domain, the cookie
becomes cross-site and browsers will drop it. That route needs
`SameSite=None; Secure` on the cookie plus a matching `CORS_ORIGINS` — more
moving parts for no benefit. Use the rewrite.

**Cloudflare Pages / Netlify** work the same way via
`frontend/public/_redirects`, which Vite copies into the build. Update the
backend host there too. Build command `npm run build`, output directory `dist`.

---

## 4. First run

1. Open your Vercel URL and **create an account** — there is no default login;
   every account comes from signup.
2. Either complete onboarding, or choose **Explore with demo data instead** to
   populate every page immediately. Demo rows are tagged, so
   **Settings → Data → Remove demo data** deletes exactly those and nothing you
   entered yourself.

## Deployment checklist

- [ ] `backend/.env` is not in the repository
- [ ] `SECRET_KEY` in production is newly generated, not the development value
- [ ] `ENVIRONMENT=production` and `DEBUG=False` on Render
- [ ] `CORS_ORIGINS` is your real frontend origin, never `*`
- [ ] `/health` reports `database.connected: true`
- [ ] The backend host in `vercel.json` (or `_redirects`) points at your Render URL
- [ ] Signup, login and logout work on the deployed URL
- [ ] Database credentials are the managed host's, not local `root`

## Things worth knowing

**Cold starts.** Render's free plan sleeps after 15 minutes of inactivity. The
first request wakes it and takes roughly 50 seconds; everything after is normal.
An uptime pinger every 10 minutes avoids this but burns your free instance
hours. Koyeb or Fly.io do not sleep.

**Rate limiting is per-process.** The AI endpoint limiter lives in memory
(`app/core/rate_limit.py`). That is correct for a single free instance. If you
ever scale to multiple workers, move it to Redis — the interface stays the same.

**Sessions are database-backed.** The JWT carries a session id and the row must
still exist, which is what makes logout and "sign out everywhere" take effect
immediately instead of waiting for expiry.

**Market data.** Without `MARKET_DATA_API_KEY`, every investment price is
labelled *user-entered* in the UI. The app never substitutes an invented price
for a real one, and a failed quote lookup leaves your entered price untouched.
